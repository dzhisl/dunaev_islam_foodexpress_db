## E. Функции и процедуры

### E.1. `add_product`, успешный вызов

В `CALL` нельзя передавать подзапросы, поэтому id берутся заранее:

```sql
SELECT count(*) AS before FROM product;

SELECT (SELECT restaurant_id FROM restaurant LIMIT 1) AS rid,
       (SELECT product_category_id FROM product_category LIMIT 1) AS cid \gset

CALL add_product(
    p_restaurant_id => :'rid',
    p_product_category_id => :'cid',
    p_name => 'Тестовое блюдо',
    p_price => 250,
    p_rating => 4.5,
    p_status => 'доступно',
    p_description => 'Описание',
    p_photo_url => NULL
);

SELECT count(*) AS after FROM product;
```

Ожидается: `after = before + 1`.
Факт: 550 и 551. Рейтинг нового блюда NULL, так как отзывов нет (BR-9.7).
Вердикт: OK

### E.2. `add_product` падает на несуществующий ресторан

Ожидается: ошибка с внятным сообщением.
Факт: `ERROR: add_product: ресторан с id 00000000-0000-0000-0000-000000000000 не существует`. Отрицательная цена тоже даёт ошибку: `цена должна быть неотрицательной`.
Вердикт: OK

### E.3. `rating_change` пересчитывает рейтинг

Отзыв можно оставить только на блюдо из своего заказа (BR-9.2), поэтому берётся позиция существующего заказа:

```sql
SELECT os.order_id, os.product_id, o.client_id
FROM order_structure os JOIN "order" o USING (order_id)
LIMIT 1 \gset

INSERT INTO review (client_id, entity_id, entity_type, order_id, description, rating)
VALUES (:'client_id', :'product_id', 'блюдо', :'order_id', 'Тестовый отзыв', 5)
ON CONFLICT DO NOTHING;

SELECT rating FROM product WHERE product_id = :'product_id';
```

Ожидается: `rating` пересчитан.
Факт: пересчитан. Сценарий из FOOD-105 тоже проверен: отзывы 3, 4, 5 дают 4.00, после удаления одного 4.50, после удаления всех NULL.
Вердикт: OK

### E.4. `rating_change`, удаление отзыва

Ожидается: если других отзывов нет, `rating IS NULL`; иначе пересчитан.
Факт: так и есть.
Вердикт: OK

### E.5. `get_statistic()`

Ожидается: нужные колонки, одна строка на ресторан, `best_user` не NULL при наличии заказов.
Факт: колонки `restaurant_name`, `best_product_name`, `total_amount`, `avg_amount`, `best_user`. 110 строк на 110 ресторанов. `best_user` это `client.login`.

### E.6. `courier_salary()`
